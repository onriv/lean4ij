# IntelliJ IDEA 2027.1 (IU-271.331 nightly): what breaks in lean4ij 0.2.8

Source: `~/.custom_configs/PetIdea/system/log/idea.log` (IDE started 2026-10-10 17:19, JBR 25,
LSP4IJ 0.21.0, lean4ij 0.2.8 == git tag `0.2.8`, which is identical in `src/` to `main` at 3bc88b3).

## 1. External (JCEF) infoview fails to start — `NoClassDefFoundError: com/intellij/ui/jcef/JBCefApp`

```
SEVERE - #c.i.i.s.i.StartupManagerImpl - com/intellij/ui/jcef/JBCefApp [Plugin: lean4ij]
Caused by: java.lang.NoClassDefFoundError: com/intellij/ui/jcef/JBCefApp
	at lean4ij.infoview.external.JcefInfoviewService.<init>(JcefInfoviewService.kt:142)
	at lean4ij.infoview.external.ExternalInfoViewService.startServer(ExternalInfoViewService.kt:192)
	at lean4ij.infoview.external.ExternalInfoViewService.<init>(ExternalInfoViewService.kt:59)
	at lean4ij.project.LeanProjectActivity.execute(LeanProjectActivity.kt:101)
Caused by: java.lang.ClassNotFoundException: com.intellij.ui.jcef.JBCefApp PluginClassLoader(... parents=module intellij.platform.collaborationTools, ..., plugin 'LSP4IJ')
```

The same exception fires again when the `LeanInfoviewJcef` tool window is opened (`UnhandledExceptions`).

Root cause: in this IDE JCEF classes are no longer in the platform core. They live in a separate bundled plugin
`com.intellij.modules.jcef` (`<IDE>/plugins/jcef-plugin/lib/modules/intellij.platform.ui.jcef.jar`, see
`<IDE>/modules/module-descriptors.jar!/plugins/intellij.jcef.plugin.xml`). A plugin that only depends on
`com.intellij.modules.platform` does not get that classloader as a parent.

Fix: `<depends optional="true" config-file="lean4ij-jcef.xml">com.intellij.modules.jcef</depends>` in `plugin.xml`.
Optional keeps older IDEs (242+) loading, where the module does not exist and JCEF is still part of the platform.

## 2. File progress line marker crashes the `LeanProjectService` coroutine — `Incorrect offsets: start=8; end=0`

```
java.lang.IllegalArgumentException: Incorrect offsets: start=8; end=0
	at com.intellij.openapi.editor.impl.MarkupModelImpl.addRangeHighlighter(MarkupModelImpl.java:266)
	at lean4ij.project.LeanFile.tryAddLineMarker(LeanFile.kt:173)
	at lean4ij.project.LeanFile$1.invokeSuspend(LeanFile.kt:96)
```

`tryAddLineMarker` bumps the start line from 0 to 1 and clamps the end line to the document size, so a processing
range `[0, 0)` (or any range past EOF) yields `startOffset > endOffset`. The first call at `LeanFile.kt:96` is outside
the `try`, so the whole per-file coroutine dies (`UnhandledExceptions`, "Plugin to blame: lean4ij"). Related upstream
issue: https://github.com/onriv/lean4ij/issues/148.

Fix: skip ranges with `endLineOffset < startLineOffset`.

## Build toolchain findings

- IDE 271.331 ships Kotlin stdlib with metadata version 2.4.0 (checked in `lib/util-8.jar!/META-INF/kotlin-stdlib.kotlin_module`),
  so the plugin must be compiled with Kotlin ≥ 2.4 (was 2.1.20). Bumped to 2.4.21.
- 271.* nightlies are not published to `https://www.jetbrains.com/intellij-repository/{releases,snapshots}`
  (latest release 2026.2.3, latest EAP 263.6259.32). Compile against the installed IDE with
  `./gradlew buildPlugin -PplatformLocalPath="/Users/vyacheslav.moklev/Applications/Pet IDEA.app/Contents"`.
- IntelliJ Platform Gradle Plugin bumped 2.10.5 → 2.19.0, Gradle wrapper is 9.3.1.

## Compile-time differences found while building against 271.331

- Platform jars are class file version 69 (Java 25): javac/Grammar-Kit on a JDK 21 toolchain fail with
  `UnsupportedClassVersionError`. Solution: `jvmToolchain(25)` + `jvmTarget`/`release` = 21 + explicit
  `java.sourceCompatibility/targetCompatibility = 21` (otherwise KGP reports "Inconsistent JVM-target compatibility").
- The archived `org.jetbrains.grammarkit` Gradle plugin cannot build its classpath from the new modular IDE layout
  (`NoClassDefFoundError: com/intellij/openapi/util/KeyedExtensionCollector`). Migrated to the
  `org.jetbrains.intellij.platform.grammarkit` subplugin (`generateParser`/`generateLexer`, `grammarKit()`/`jflex()` deps).
- Not on the compile classpath via `com.intellij.modules.platform` anymore, added as `bundledModules`:
  `intellij.platform.execution(.impl)` (RunManager, ConfigurationTypeUtil, ProgramRunnerUtil),
  `intellij.platform.buildView` (com.intellij.build.*), `intellij.platform.externalSystem(.impl)`
  (AutoImportProjectTracker), `intellij.platform.ui.jcef` + `intellij.libraries.jcef`.
- `instrumentCode` needs `com.jetbrains.intellij.java:java-compiler-ant-tasks:<build>` which does not exist for
  nightlies → disabled (no .form files in the project).
- API changes: `Editor.getVirtualFile()` is nullable; `SyntaxHighlighter.getTokenHighlights(IElementType)` parameter
  is `@NotNull`; lsp4j 1.0.0 (bundled by both IU 271 and LSP4IJ 0.21) changed `Diagnostic.getMessage()` to
  `Either<String, MarkupContent>` → `lean4ij.util.Lsp4jCompat.messageOf`.
- Kotlin 2.4 reports `e is ExecutionError` inside `catch (e: Exception)` as an error ("Check for instance is always false").

Result: `./gradlew buildPlugin -PplatformLocalPath=...` → `build/distributions/lean4ij-0.2.9-beta.1.zip`.
